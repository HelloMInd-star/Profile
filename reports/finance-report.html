1执行摘要

先给结论，再给证据。

一句话定位

Y.Mine 不应被卖成「像巴菲特的你」，而应是 一个能看见自己偏差、约束自己行为、复现自己研究、并把每一步留给审查的个人投资决策系统。

它的真正资产不是"人格"这个叙事外壳，而是三层可被逐行验证的硬能力：① 自建的估值与风险计量引擎（数学正确、有单元测试）；② 11 段式可审计的投研决策流水线；③ 把 LLM 严格收敛为叙事层的 AI 工程化架构。

三个最有价值的判断

有证据

赛道定位：不是智能投顾

它缺两张牌：证券投资咨询牌照，以及账户内的执行/托管能力。因此正确坐标是 AI 投研决策工作台 + 行为画像层 + 持牌投顾适配层 的交集，而非"智能投顾"。

差异化

蓝海在"人格语义"，不在"行为数据"

传统风险问卷（C1-C5 / R1-R5）已是红海；但跨场景行为 → 人格向量 → 可审计匹配尚无公开可核验的规模化成熟先例。这是机会，也是需要自证的部分。

风险

最大风险是合规，不是技术

向中国个人投资者输出"买什么/仓位多少"即触发证券投资咨询持牌要求；人格画像不得替代法定适当性评估；跨场景行为数据触及敏感个人信息单独同意规则。

2核心抽象：人格向量作为统一数据契约

这是整个产品矩阵（12 个应用）真正的地基，也是被"人格""MBTI"这些词遮蔽掉的最值钱部分。

Y.Mine 的所有模块共享同一个抽象：把人的状态表示为一组可计算的向量，再让不同业务模块消费这组向量。

两套向量体系

六维人格向量（调酒 / 感官模块）

TOL 容错SPD 速度INF 信息 ENT 热情LEAD 主导VIS 直觉

OCEAN 大五人格 → 六维映射，同一组向量向下派生调酒、对局、气味三类感官模块。15 个纯函数引擎 + 13 个路由页。

实锤：profileToVector OCEAN→六维、cocktailEngine 余弦相似度推荐、personaFusionEngine 多人格融合、feedbackEngine 反馈校准

五维决策向量（金融模块）

riskTolerance 风险偏好timePreference 时间偏好 executionDiscipline 执行纪律reflectionDeviation 路径预判 aimPrecision 决策观察

这五维同时是 投资人匹配引擎的输入 和 用户画像的输出，构成"行为采集 → 建模 → 画像 → 匹配 → 建议"的闭环。

实锤：investorEngine.js（24.8KB）五维加权欧几里得距离匹配

为什么这个抽象值钱：它让"人格"从一种文案修辞，变成了可复用、可计算、可跨模块迁移的数据结构。同一套向量在调酒台决定风味配比，在金融端决定风险预算与资产匹配——这不是 12 个独立项目的拼盘，而是一个有内核的产品矩阵。

设计上的三个亮点

① 人性偏差校验是独立环节

第 8 段 rationalityScore 把"情绪与认知偏差"作为流水线的一等公民，而不是事后提醒。这与传统投研工具形成结构性差异。

② 熔断风控在下单之前

第 9 段风控前置到第 10 段执行之前——顺序本身就是产品价值观的表达：先设边界，再谈操作。

③ 绩效归因闭环

第 11 段把结果回流，形成"决策 → 执行 → 归因 → 再决策"的回路，为长期的行为数据积累留出接口。

建议的产品化动作：把这 11 段公开为可保存、可导出的 「决策审计链」——每段记录：数据时间戳、来源、用户自定义参数、自动计算值、LLM 叙事版本、用户对关键假设的确认。这既区别于一问一答的通用 AI，也满足未来持牌合作方对留痕的要求。

4估值与风险计量引擎：数学是站得住的

我逐行读过源码，这是整个项目最硬的部分——不是调包，不是包装，是真实实现的金融模型。

估值模块（corporateFinance.js 34KB）

  • 四法交叉验证：DCF / WACC / APV / FTE
  • CAPM 权益成本求解
  • MM 定理与最优资本结构求解
  • 并购估值、IRR

四法并列而非单一路径，结果可互相印证——这是专业投研的做法。

风险模块（quantEngine.js 82KB）

  • 参数法 VaR / CVaR（95% / 99%）
  • Altman Z-Score 破产风险
  • 最大回撤、IRR
  • Kelly 仓位最优下注比例

全部纯函数实现，配套 quantEngine.test.js（16KB）单元测试。

WACC 实现代码（原文节选）

// quantEngine.js — 加权平均资本成本
const costOfEquity      = r + b * mp;        // CAPM 权益成本
const afterTaxCostDebt = cod * (1 - tr);    // 税后债务成本
const wacc = costOfEquity * ew + afterTaxCostDebt * dw;

税后债务成本处理、CAPM 权益成本、权重校验——教科书级正确，不是调包糊的。

必须坦诚的三处局限

① 32 只预设资产的因子是硬编码静态快照，且已过期。 PRESET_ASSETS 中 NVDA basePrice: 875、TSLA 245——拆股前的旧数据；PE/ROE/营收增速均为写死常量，不是从 API 拉取。行情是实时的，估值因子是静态的。
② WACC 参数口径是美股的，套在 A 股上不成立。 默认 rf = 4.2%、marketPremium = 5.5%、taxRate = 21%（美国联邦税率）——全部美股口径。但资产池含茅台、招行、宁德，中国法定税率 25%。
③ VaR 只有参数法（正态假设），蒙特卡洛很薄。 computeVaR 是纯 z-score 法（95%→1.645），无历史模拟法、无 t 分布、未处理肥尾；"蒙特卡洛"在 82KB 引擎中仅出现 1 处。对比基准 benchmarkReturn 默认 8% 为硬编码，非真实指数。

当前边界与计划："行情实时拉取；估值因子为演示用静态预设，接财务数据 API 在 P3 迭代计划内；参数默认值可交互调整，分市场参数模板为已知改进点；VaR 目前为参数法，历史模拟法在规划中。"

5用户画像与洞察简报引擎

这部分把"用户画像 / 用户分层 / 个性化推荐 / 闭环 / 场景化风险评估"五类产品能力从代码层还原出来。

insightBriefEngine.js 的 generateInsights() 输出结构：

{
  summary,              // 画像总述
  strengths[],          // 前 3 高分维度 → 优势
  risks[],              // 低分维度 + 认知内耗 → 风险
  suggestions[],        // 每条风险挂一条改进建议
  archetype,            // 人格原型分类
  todayFocus, tarotInfluence, musicAlignment
}

即：六维向量 → 人格原型分类 → 取前 3 高分维度标为优势、后 2 低分维度标为待发展风险 → 每个风险挂一条改进建议。这是一套完整的用户分层诊断引擎。

产品能力的代码侧证据："用户画像""用户分层""个性化推荐""闭环""场景化风险评估"五类产品能力全部在代码中落地，且以引擎化、可复用的模块形式存在。

620 位投资人基准库：风格坐标系

传播性最强的功能，也是风险最高的功能。

数据库构成

benchmarkProfiles.js（27.3KB）：10 位投资人 + 10 位创业家，统一人物源。

沃伦·巴菲特查理·芒格乔治·索罗斯 瑞·达利欧彼得·林奇孙正义 本杰明·格雷厄姆约翰·保尔森卡尔·伊坎 约翰·邓普顿

每人含：MBTI 标签、五维向量、决策风格、心智模型、代表案例（含年份）、语录、人生节点，甚至延伸到味觉偏好与消费画像（供调酒模块复用）。

匹配机制

// investorEngine.js
weightedEuclideanDistance(userVector, invVector)
// 维度权重：
riskTolerance       1.2  // 风格核心
timePreference      1.0  // 长线 vs 短线
executionDiscipline 0.9  // 可培养
reflectionDeviation 0.8
aimPrecision        0.7

相似度分四档：高度契合 ≥85 / 较为相似 ≥70 / 部分相似 ≥55 / 风格迥异 <55；每条匹配输出共同点、差异点、提升建议，并支持相似度趋势追踪。

三个必须认识到的风险：
  1. 投资风格标签未必有权威、可复现的行为基准——这些参数是你自己标定的。
  2. 用户可能与某位投资人历史表现相似，却不共享其资金期限、流动性、杠杆和承受力。
  3. 名人对标容易诱发"我也该高集中 / 高杠杆 / 逆向交易"的误读。
推荐的产品机制：把相似度降为「叙事与反思卡片」，与法定风险等级、资金用途、期限、硬风险预算并列展示。当人格偏好与 VaR 限额冲突时，系统优先显示冲突和"为什么不能按偏好执行"，而不是自动给出更激进的组合。
核心判断：可解释的自我约束，比人格匹配本身更有商业价值。

7AI 工程化：把 LLM 关进笼子里

这是 2026 年最稀缺的能力之一——多数人会让 LLM 直接算数，你没有。

架构范式的核心决策：数字全部本地计算，LLM 只做叙事层。这意味着 AI 可以胡说，但不会算错账——风控边界由代码守，不由模型守。

已实现的工程化控制

  • 9 条 Prompt 模板注册表，非自由文本拼接
  • JWT 网关鉴权
  • 参数白名单（防越权调用）
  • 护栏：max_tokens / temperature 限制
  • Key 仅服务端持有，前端不暴露
  • 未登录时自动降级为本地模板，服务不中断

待补的合规项

  • P0 AI 生成内容显式标识（《AI 生成合成内容标识办法》2025 起要求）
  • P0 输出附：模型版本、生成时间、引用来源
  • P1 人工复核状态标记、用户反馈入口
  • P1 所有投资叙事的免责声明与合规审阅

三源行情兜底架构

接入东方财富 + 新浪 + 腾讯三源行情合并，任一源失效自动降级，覆盖 32 只美股 / 中概 / A 股标的，支持 K 线实时渲染与 CSV 导出。行情抓取模块 eastmoneyData.py 40KB。

9竞品格局：五类价值网的竞争

中国竞争的核心是流量、数据与持牌闭环；海外竞争的核心是低成本配置与自动化。

赛道坐标：Y.Mine 处在四个成熟市场的交界

相邻赛道核心交付典型商业模式与 Y.Mine 重合度不应混同之处
行情资讯与社区行情、资讯、讨论、选股广告、导流、基金销售中低Y.Mine 明确不做资讯
专业投研终端数据、财务模型、筛选、研报席位订阅、机构授权高目标用户是个人，非机构

12合规红线：这不是可选项

在中国做"基于人格画像的资产匹配"，以下四条是硬约束。

① 智能投顾 = 证券投资咨询，须持牌。 陕西证监局明确：涉及证券期货的"智能投顾"属于证券投资咨询业务，须取得证监会许可的经营证券期货业务许可证；未经批准擅自开展，存在非法证券期货活动和刑事法律风险。
② 人格画像不得替代法定适当性。 证监会适当性指引要求持续评估，普通投资者分 C1-C5、产品分 R1-R5，禁止诱导或误导。人格画像必须作为独立洞察放在法定测评之后，明确标注"不等于风险等级、不得用于绕过准入、可关闭删除"。
③ 多场景行为数据触发敏感信息规则。 《个人信息保护法》将金融账户、医疗健康、生物识别等列为敏感个人信息，处理需特定目的 + 充分必要性 + 单独同意。健身数据、音乐偏好、人格向量都应视为高风险画像。
④ 自动化决策需可解释、可拒绝。 法律要求自动化决策透明公平；对个人权益有重大影响的决定，个人有权要求说明并拒绝仅由自动化决策作出。"人格分低于阈值即禁止某类资产"这类功能必须设人工复核、申诉与退出机制。

13战略建议：优先级排序

把产品拆成四层，不要后两层前置为获客承诺。

优先级方向用户价值商业可行性合规难度
P0行为偏差校验与熔断建议抑制追涨杀跌、过度杠杆、情绪交易高（订阅 / B2B）中
P0多源估值 / 风险工作流降低个人投研的信息处理成本高中
P1人格原型 + 投资人对标提升自我认知与留存中高
P2持牌资产配置匹配实现交易闭环高（若持牌）极高
P2跨场景原始行为数据采集增加数据维度不确定极高
关键设计原则：硬风险指标给出边界，人格语义负责解释和干预。不能让"像达利欧"之类的相似度直接改变仓位。人格标签最可能提升"用户参与和偏差觉察"，而 VaR/CVaR、Kelly、Z-Score、估值模块更可能提升"决策质量"——两者必须分离。

最低成本的下一步（两天可完成）

当前最大短板是"零用户数据"，但应届生阶段这情有可原。不需要等真实用户，用种子样本自证即可：

  1. 用六维向量对 10 位你熟悉的人 做画像，看输出的人格原型与实际认知的吻合度
  2. 用历史行情跑一次 VaR 回测，看实际突破次数是否落在 95% 置信区间内
  3. 把 Mock 登录换成不记名行为埋点（调酒项目的埋点已选型待接，正好并过去）

完成后即可写出：「以 10 名种子用户完成画像准确性验证，人格原型匹配度 X%；VaR 回测突破率落在理论置信区间内」——这比"100 个陌生用户"更硬，因为它证明你会设计验证方法。

三个待验证的效度问题（决定产品生死）

区分效度

六维向量能否区分客观财务约束、风险承受能力与短期情绪？

预测效度

人格分数能否预测未来回撤反应、换手率或组合偏离，且优于年龄、收入、期限等低成本变量？

干预效度

基于画像的提醒是否降低非理性交易，而非提高焦虑或促成交易？

在这三项有证据前，产品材料应使用"偏好与决策风格洞察""行为偏差提示"，避免"风险评级""收益适配""巴菲特式投资者"等易被理解为投资结论的表述。

三大战略框架的推导

上述 P0-P2 排序并非直觉，而是三套框架的交叉结果。

① Ansoff 增长矩阵 —— 往哪个方向长

战略方向具体动作风险优先级
市场渗透现有产品 → 现有市场扩大标的覆盖（32 → 更多）、提升画像准确性、补充回测低当前主攻
产品开发新产品 → 现有市场增加决策复盘 / 行为日记 / 偏差提醒，强化留存中当前主攻
市场开发现有产品 → 新市场B2B2C：引擎输出给持牌机构，由其承接牌照与交易中高中期
多元化新产品 → 新市场出海 / 跨资产类别（加密、期权）高暂缓

结论：Ansoff 的四个象限中，风险最低的两个（渗透 + 产品开发）应优先；"市场开发"即 B2B2C 是唯一能绕开牌照硬约束的规模化路径；"多元化"在核心未验证前不应启动。

② BCG 矩阵 —— 模块怎么排资源

口径声明：BCG 严格依赖市场份额与增长率数据，而本项目无市场数据。此处为定性类比——用"用户价值确定性"替代相对份额、用"投入需求"替代增长率，用于资源排序，不构成市场份额判断。
象限对应模块判断依据资源决策
⭐ 明星行为偏差校验 + 熔断建议用户价值最直接（抑制追涨杀跌），且与 Game-OS 内核同源，是差异化所在重投入，作为核心叙事
🐄 金牛估值 / 风险引擎（DCF·WACC·APV·VaR·CVaR）数学正确、有单测、已是稳定资产，构成技术壁垒维护 + 守成，不轻易重构
❓ 问题LLM 叙事层体验增益明显，但成本与幻觉风险并存，效果未验证受控投入，严格收敛在叙事层

③ OLI 范式 —— 要不要跨区域 / 出海

OLI（Ownership-Location-Internalization）原用于解释对外直接投资。这里借用它判断"能力应当自建自营，还是授权给外部"这一组织边界问题。

维度本项目状况推论
O 所有权优势六维人格向量 + 可审计投研流水线是独特抽象，跨场景可复用优势存在，且可脱离具体业务独立存在 → 具备授权的可行性
L 区位优势中国个人投资者基数大；但监管明确、牌照门槛高区位对持牌方有利，对无牌照的我方不利 → 不宜直接面向 C 端做交易闭环
I 内部化优势自建引擎可保证数学正确性与可审计性；授权则失控风险高核心引擎应内部化（不外包），但面向用户的交付应外部化给持牌方
OLI 的合成结论：O 有、L 不在我方、I 在核心引擎——三者交叉指向唯一可行解：核心能力内部化自持，牌照与交易环节外部化给持牌机构，即 B2B2C。这与第 10 章差异化定位的结论独立得出、相互印证。

14总结与核心价值

这份分析的价值不在"人格金融孪生"这个叙事外壳，而在于三层可被逐行验证的硬能力。

一句话说清：这个产品是什么

"一个把投资者行为数据抽象成可计算人格向量、再驱动个性化投研决策的个人投资操作系统。它的核心不是荐股，而是帮人看见并约束自己的决策偏差。"

差异化位置：补上"我是谁 → 我该怎么决策"这一层

"市面上的工具要么给数据（东财/Wind），要么给配置（且慢/摩羯智投），中间缺一层——把'我是谁'翻译成'我该怎么决策'。我做的是这一层：11 段流水线 + 人格向量 + 自建估值风控，且每段都可审计。"

验证体系：三层递进

"三层验证：底层是单元测试覆盖金融模型（WACC 四法交叉验证互相印证）；中层是 20 位投资人风格基准，用户向量与标杆做距离匹配，输出相似度和差异诊断；上层是历史行情的 VaR 回测。下一步是种子用户画像一致性验证。"

风险与合规边界：前置熔断 + B2B2C 商业化

"合规。向个人投资者输出买卖建议需要证券投资咨询牌照，人格画像也不能替代法定适当性评估。所以我的设计是：硬风险指标给出边界，人格语义只做解释和干预，相似度降为反思卡片而非配置依据。商业化走 B2B2C——引擎给我，牌照和交易给持牌机构。"

核心结论

这个项目的价值不在"人格金融孪生"这个漂亮的名字，而在于它证明了三件事：能把金融工程真正实现出来（不是调包）、能克制地工程化 AI（不让 LLM 算数）、能看见合规边界（不把相似度当配置依据）。
